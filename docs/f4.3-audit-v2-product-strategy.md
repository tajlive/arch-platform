## 1. Audit v2 — nye moduler (Tom-beslutninger: 1C begge lag, 2A+B teknisk+forretning, 3A AI, 4A PageSpeed, 5C begge formål)

### 1.1 Norge bedriftsdata (Brreg)
- Kilde: `data.brreg.no/enhetsregisteret/api` (åpne data, NLOD-lisens, gratis, ingen nøkkel).
- Sjekker: firma finnes (org.nr), navn, stiftelsesdato, ansatte, næringskode, organisasjonsform,
  registrert i MVA, konkurs/under avvikling, roller (styre/daglig leder), siste årsregnskap
  (driftsinntekter, resultat, ansatte).
- **Konsistenssjekk:** matcher navn/org.nr/opplysninger på nettsiden mot Brreg?
  Avslører «gamle opplysninger som ikke stemmer» (Tom).
- Output-status: `observed` — kilde er offentlig register.

### 1.2 Domenedata (Norid)
- Kilde: `whois.norid.no` / RDAP (`rdap.norid.no`, produksjons-RDAP åpnet 27. november per Norid —
  bruk whois inntil videre).
- Sjekker: registrar, opprettet, sist endret, DNSSEC, eierinformasjon (der tilgjengelig).

### 1.3 Bransjekontekst (SSB)
- Kilde: SSB Statistikkbanken API (åpen, CC BY 4.0).
- Gir: antall foretak/omsetning i kundens næring (næringskode → SSB-tabell) — «hvordan ligger de an».

### 1.4 Compliance Norge — ALLTID signal, aldri dom
- **Regel:** funn formuleres som «signal» / «potential concern» / «krever juridisk vurdering».
  Aldri «compliant»/«ikke-compliant». (KLA-264 trust-claims-policy gjelder også her.)
- Sjekker (deterministisk, passivt):
  - Cookie/CMP: finnes banner? finnes «Avvis»-knapp (ekomloven § 3-15 krever reelt valg)?
    forhåndsavkryssede kategorier?
  - Cookies satt FØR samtykke (headless Chrome + CDP Network: Set-Cookie + trackere lastet på første treff).
  - Personvernerklæring: finnes? lenket fra footer? innholdssignaler (behandlingsansvarlig, kontakt).
  - Tredjeparts-trackere (GA/Meta Pixel) lastes uten samtykke.
  - Ekstern Google Fonts (IP-data til Google — signal).
  - E-handel: pris inkl. mva, angrerett, klageadgang (prisopplysningsforskriften, angrerettloven).
  - UU-signaler: alt-tekst, aria, overskriftsstruktur, kontrast (uutilsynet-kontekst, WCAG A/AA).

### 1.5 «Hva en hacker ser» (sikkerhetsdybde)
- Security headers med **gradering A+–F** (securityheaders.com-modellen): CSP, HSTS, X-Frame-Options,
  X-Content-Type-Options, Referrer-Policy, Permissions-Policy.
- **SPF/DKIM/DMARC** via DNS (spoofing: «hvem som helst kan sende e-post som om de er dere») + CAA.
- **Subdomene-oppdagelse via crt.sh** (Certificate Transparency, gratis, passivt) — glemte
  subdomener, staging, admin-paneler = attack surface.
- Versjonslekkasjer: Server/X-Powered-By-headers, meta generator (WordPress/jQuery-versjoner),
  gamle rammeverk-signaturer (jQuery 1.x/2.x, gammel Bootstrap).
- Cookie-attributter: HttpOnly, Secure, SameSite.
- TLS: sertifikat-alder, protokoller (TLS 1.0/1.1 = signal), utløpsdato.
- Eksponerte filer (passivt): /.env, /.git, backup-filer (kun tilstedeværelse via GET-status,
  aldri innhold).

### 1.6 Tilstedeværelse
- Google Maps/Google Business: firma finnes? anmeldelser (antall + snitt), kategori, lenke.
- Sosiale medier: linker fra nettsiden (Facebook/Instagram/LinkedIn/TikTok/YouTube) — profil finnes?
  siste aktivitet? konsistent navn/logo?
- NAP-konsistens: navn/adresse/telefon på tvers (nettside ↔ Brreg ↔ Google Maps).

### 1.7 AI-analyse (DeepSeek Flash ~$0.14/$0.28 per M)
- Innholdskvalitet, tone, aktualitet (gamle datoer, «© 2021», døde referanser), UX-prosa.
- Skriver executive-språk i rapporten. Alltid reproduserbar: LLM-svar lagres i evidence med prompt.

### 1.8 PageSpeed Insights (Google API)
- Ekte Chrome User Experience Report-data (LCP/INP/CLS) + Lighthouse-labdata. Gratis-token.

### 1.9 Verktøy vi ikke gjenoppfinner, men bruker (gratis)
- crt.sh (subdomener), Norid whois, Brreg API, SSB API, Wayback Machine CDX-API (historikk —
  «hva stod der før»), Google Safe Browsing-lookup, VirusTotal-omdømme (rate-begrenset).

## 5. Søkebibliotek — verifiserte endepunkter (dybdesøk 2026-08-14)

Alle endepunkter testet live 2026-08-14. Regler i fet skrift er permanente.

### 5.1 Brreg Enhetsregisteret (`data.brreg.no/enhetsregisteret/api`)
- Enhetssøk: `GET /api/enheter?navn=<firma>&size=5` — header `application/vnd.brreg.enhetsregisteret.enhet.v2+json`.
- Roller (organisasjoner): `GET /api/enheter/<orgnr>/roller` — åpen, ingen nøkkel.
- **Endringsfeed (Monitor-produktet!):** `GET /api/oppdateringer/enheter?dato=...` —
  **dato MÅ være fullt ISO-tidspunkt:** `yyyy-MM-dd'T'HH:mm:ss.SSS'Z'` (f.eks. `2026-08-14T00:00:00.000Z`).
  Dette gir automatiske endringsvarsler for Arch Monitor uten polling av hele registeret.
- **Autorisasjonsgrense:** roller som involverer privatpersoners fnr krever Maskinporten-scope
  (`brreg:data:enhetsregisteret:roller`). Vi bruker KUN det åpne API-et (organisasjoner/roller uten fnr).
- Regnskap: `GET /api/enheter/<orgnr>` gir siste årsregnskap i enhetsobjektet (ingen egen endpoint nødvendig).
- Signatur/prokura og reelle rettighetshavere finnes som egne åpne datasett (Compliance-produktet senere).

### 5.2 Norid RDAP — PRODUKSJON, bruk RDAP (ikke whois)
- **`https://rdap.norid.no/domain/<domene>`** er i produksjon (åpnet 27. november 2025).
  REST/JSON — erstatter whois. whois.norid.no fases ut.
- **Regel — eTLD+1:** RDAP-lookup MÅ gjøres mot det registrerbare domenet.
  `rdap.norid.no/domain/no.issworld.com` → 404 «Norid is not authoritative» (subdomene under issworld.com).
  Audit-verktøyet må derfor: hvis domenet ikke er `*.no`, slå opp rotdomenet (issworld.com),
  og merke «.no-status: N/A (utenlandsk domene)» i rapporten.

### 5.3 SSB Statistikkbanken — PxWebApi v2 (GET, åpen, ingen nøkkel)
- **`https://data.ssb.no/api/v0/no/...`** — v2 støtter GET med query i URL (ingen POST nødvendig).
- 7 000 tabeller; bransjekontekst = tabell med næringskode (f.eks. 45.x bilglass, 81.x FM/renhold).
- Konsoll: ssb.no/statbank for tabell-id-er; PxWebApi v2-brukerveiledning: ssb.no/api/pxwebapiv2.

### 5.4 E-post/DNS-sikkerhet — 2026-standarden (utvidelse av §1.5)
Planen dekker SPF/DKIM/DMARC — **legg til, i denne rekkefølgen:**
1. **DMARC-policy-gradering:** `p=none` (overvåk), `p=quarantine`, `p=reject` (blokk). Kun 14,7 % av domener har
   full SPF+DKIM+DMARC (Red Sift 2026) — dette er vårt vanligste salgsfunn.
2. **MTA-STS:** `dig TXT _mta-sts.<domene>` + `https://mta-sts.<domene>/.well-known/mta-sts.txt` — håndhever
   e-post-TLS (mot MITM).
3. **TLS-RPT:** `dig TXT _smtp._tls.<domene>` — rapportering for e-post-TLS-feil.
4. **BIMI:** `dig TXT default._bimi.<domene>` — merkevareverifisert logo i innboks (Premium-signal).
5. **DNSBL/omdømme:** sjekk MX/IP mot zen.spamhaus.org (f.eks. `dig +short <ip-reversert>.zen.spamhaus.org`).
6. **DNSSEC-kjede:** `dig +dnssec DNSKEY <domene>` — AD-flagget valideres.
7. **CAA:** `dig CAA <domene>` (allerede i planen — behold).
- Kildehenvisning for gradering: securityheaders.com-modellen for HTTP, EasyDMARC/Red Sift-metodikk for e-post.

### 5.5 Øvrige passive kilder (allerede i planen — bekreftet)
- crt.sh: `GET https://crt.sh/?q=%25.<domene>&output=json` (subdomener).
- Wayback CDX: `GET http://web.archive.org/cdx/search/cdx?url=<domene>/*&output=json&limit=50`.
- Google Safe Browsing: `https://transparencyreport.google.com/safe-browsing/search?url=<domene>` (skrap, rate-begrenset).

### 5.6 Søkemønstre (permanente regler)
1. **Domene-normalisering først:** alltid eTLD+1 for DNS/RDAP/crt.sh; subdomene kun for HTTP-crawl.
2. **Konsistenssjekk kjører alltid:** nettside-navn/org.nr ↔ Brreg ↔ Google Maps (NAP).
3. **Signal-ord:** alle compliance-funn = «signal», aldri «brudd» (KLA-264).
4. **Bevis-policy:** hvert funn lagrer kilde + rådata i evidence-JSON (reproduserbart).
5. **Rate-limits:** crt.sh (1 req/s), VirusTotal (4/min uten nøkkel), Brreg (åpent, men vær hensynsfull).
