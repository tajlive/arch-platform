# F4.1 — Kommersiell modell: Audit → Build → Managed

> Forretningsmodellen er trappetrinn, ikke én stor visjon. Kunden kjøper først et
> konkret resultat; Arch-plattformen er motoren som gjør leveransen raskere og bedre.

## Første tilbud (ordrett, enkelt)

> «Vi analyserer programvaren deres uten å endre noe, finner risiko, teknisk gjeld og
> automatiseringsmuligheter, og gir dere en prioritert plan for hva som faktisk er verdt å gjøre.»

**Ikke** start med «vi bygger en AI-plattform». Arch er motoren bak leveransen —
når kunden ser resultatet, selger Arch Build (og senere Arch Managed) seg selv.

## Tre trappetrinn

| Produkt | Hva kunden kjøper | Når |
|---|---|---|
| **Arch Audit** | En forståelig rapport + konkret tilbud | Inngangsprodukt — første møte |
| **Arch Build** | Implementering av godkjente tiltak | Naturlig salg etter funnene |
| **Arch Managed** | Løpende drift/automatisering | Abonnement etter Build |

## Hvorfor dette vinner

- **Kunden risikerer ingenting:** read-only, ingen endringer, kun å se koden.
- **Verdien er konkret:** risiko + teknisk gjeld + automatiseringspotensial — ikke «autonom AI-plattform».
- **Upsell er logisk:** Build Proposal-utkastet ligger allerede i rapporten (auto-generert).
- **Managed er naturlig:** etter Build eier Arch driftsautomatikken.

## Hva som IKKE selges på første møte

- Hele «autonom AI-plattform»-historien.
- Arch Control Center (internt verktøy).
- Tekniske detaljer om Knowledge Graph/Factory/Governance.

## Regler for kommersiell copy (fra Klarpakke-lærdommer)

- **Alltid fakta:** aldri fabrikkerte tall, brukertall eller «sertifisert»-påstander.
- **Ingen datoer/løfter om tidspunkt** for betaling/lansering.
- **Juridiske påstander (GDPR m.fl.) = forbudt** uten kvalifisert gjennomgang — gjelder også i salgs-copy.
- Score er «evidensbasert vurdering», aldri «sertifisering».
